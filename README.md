**VPN Web Cabinet** — полноценное веб-приложение на базе FastAPI и Jinja2, разработанное специально как альтернативный интерфейс для пользователей из РФ, у которых заблокирован Telegram. 

Приложение работает **с той же базой данных**, что и Telegram-бот (`vpn_tg`), полностью дублируя ключевую функциональность: управление ключами доступа, биллинг, реферальную систему, промокоды и техподдержку через тикеты.

---

## ⚡ Ключевые фичи & Безопасность веб-слоя

- **🔄 Синхронизация «из коробки»**: Полная интеграция с бэкендом бота. Управление подписками, балансом и серверами происходит в едином пространстве данных.
- **🔒 Защита веб-интерфейса**: Безопасное хеширование паролей через `bcrypt`, встроенная защита от межсайтовой подделки запросов (`CSRF`) и строгий `Rate-Limiter` на попытки входа (максимум 5 запросов в 15 минут).
- **🚀 Оптимизация SQLite (WAL)**: Корректная параллельная работа сайта и бота с одной базой данных благодаря включению режима *Write-Ahead Logging* и настройке `busy_timeout=5000`.
- **🔏 Бесшовная миграция пользователей**: Удобная активация аккаунтов существующих клиентов бота на сайте через временные 7-дневные защищенные коды авторизации без потери баланса и рефералов.

## 📂 Архитектурная структура проекта

```text
app/
  ├── config.py         # pydantic-settings: чтение независимого .env и .env бота
  ├── db/               # Зеркало ORM-моделей бота и репозиториев (без собственных миграций)
  ├── services/         # Изолированный сервисный слой (billing, provisioning, xui, yookassa)
  ├── web/
  │   ├── security.py   # Механизмы авторизации, bcrypt, rate-limit, CSRF
  │   ├── vless.py      # Генератор vless-ссылок + TTL-кэширование inbound-параметров
  │   ├── services.py   # Логика обработки успешных оплат и вебхуков
  │   └── routes/       # Контроллеры (public, auth, cabinet, buy, admin, webhooks)
  ├── templates/        # Шаблоны Jinja2 (Тёмная тема, адаптивная верстка)
  ├── static/           # Статические ресурсы и стили Bootstrap 5 (CDN)
  └── cli.py            # Утилиты командной строки (управление ролями админов)
tests/                  # Набор из 30 тестов (pytest + httpx ASGI)
deploy/                 # Конфигурационные файлы для systemd и Nginx
```

## 🛠️ Локальный запуск и Развертывание

### 1. Настройка окружения и зависимостей
```bash
# Создание виртуального окружения
python3 -m venv .venv --without-pip
.venv/bin/python <(curl -sS https://bootstrap.pypa.io/get-pip.py)

# Установка пакетов для разработки и продакшена
.venv/bin/pip install -r requirements.txt -r requirements-dev.txt
```

### 2. Привязка конфигурации
Сайт использует общие секреты с ботом (`DATABASE_URL`, `SECRET_KEY`, ключи ЮKassa). Настройте символическую ссылку на `.env` бота или скопируйте его:
```bash
ln -sf ../vpn_tg/.env .env
```

### 3. Запуск тестов и сервера
```bash
# Прогон 30 интеграционных тестов
.venv/bin/python -m pytest tests -q

# Старт локального сервера разработки (доступен на http://127.0.0.1:8000)
.venv/bin/python -m app
```

## 👥 Управление доступом (CLI)

Для создания первого администратора сайта или повышения существующего пользователя из Telegram используйте встроенные CLI-команды:

```bash
# Создание нового администратора с нуля
.venv/bin/python -m app.cli create-admin --email admin@example.com

# Повышение существующего пользователя бота до админа сайта
.venv/bin/python -m app.cli promote --telegram-id 123456789
```

## ⚠️ Важные архитектурные требования к Prod-окружению

1. **Контроль схемы БД**: Схемой данных полностью владеет репозиторий бота (`alembic`). У сайта нет собственных миграций. Перед запуском сайта примените миграцию `b4f2a0c7d901_web_accounts` в репозитории бота.
2. **Включение WAL для SQLite**: Чтобы избежать блокировок базы данных при одновременных запросах от сайта и бота, обязательно выполните на VPS:
   ```bash
   sqlite3 /opt/vpn_tg/data/bot.db "PRAGMA journal_mode=WAL;"
   ```
3. **Идемпотентность**: Логика выдачи подписок полностью изолирована. Параллельное срабатывание вебхука сайта и фоновой `reconcile`-задачи бота безопасно для состояния базы данных.
